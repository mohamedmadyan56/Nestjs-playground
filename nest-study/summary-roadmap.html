الجزء الأول: ملخص المشروع

وصف المشروع

ده مشروع NestJS يحاكي نظام عربية. فيه عربية ليها مودور (Engine) و بطارية (Battery) و تكييف (Conditioner). لما تضرب GET /car العربية تبدأ وتشتغل معاك التكييف.

كمان في Users Module كامل بعمليات CRUD (إنشاء - قراءة - تحديث - حذف) مع Validation باستخدام class-validator.

هيكل المشروع (Dependency Graph)

CarModule (الموديول الرئيسي) ├── CarController │ ├── EngineService ← من EngineModule │ └── ConditionerService ← من ConditionerModule │ ├── EngineModule │ ├── EngineService │ └── BatteryModule ← BatteryService │ └── ConditionerModule ├── ConditionerService └── EngineModule (معاد استيراده)

الموديولات والملفات

  • BatteryModule → BatteryService (بتشغل البطارية)
  • EngineModule → EngineService (بتشغل الموتور، محتاجة BatteryService)
  • ConditionerModule → ConditionerService (بتشغل التكييف)
  • CarModule → CarController (الراوت الرئيسي)
  • UserModule → UserController + UserService (CRUD كامل للمستخدمين)

الجزء التاني: الأخطاء اللي اتصلحت

الخطأ الأول: ملف battery.module.ts ناقص

❌ الخطأ:

لما حاولنا نعمل Build ظهر error:

// TS2305: Module '"../battery/battery.module"' has no exported member 'BatteryModule'
✅ الحل:

فيه ملف battery.module.ts كان فيه imports بس مفيش @Module({}) ولا export class BatteryModule.

أضفنا:

@Module({ providers: [BatteryService], exports: [BatteryService] }) export class BatteryModule {}

الخطأ التاني: EngineModule مش مصدّر EngineService

❌ الخطأ:

لما شغلنا السيرفر ظهر runtime error:

// Nest can't resolve dependencies of the CarController // Please make sure that the argument EngineService at index [0] is available in the CarModule
✅ الحل:

EngineModule كان عنده EngineService كـ provider بس مش مصدّره (exports). فأي موديول تاني (زي CarModule) معرفش يوصل ليه.

أضفنا exports: [EngineService]:

@Module({ imports: [BatteryModule], providers: [EngineService], exports: [EngineService] // ← دي الإضافة })
✅ دلوقتي السيرفر شغال ومردود GET /car:
["Battery is Working you can start your engine engine is working ","ConditionerON"]

✏️ ملاحظات تانية في الكود

  • خطأ إملائي: فيه فولدر condintioner/ (غلط) والتاني conditioner/ (صح). الموديول مستورد من الفولدر الغلط لكن الشغلة شغالة عادي.
  • UserModule ناقص: مش مضيف UserService في providers. لو المستخدم حاول يستخدم `UserModule` هيطلع error.
  • Duplicate Decorator: في create-User.dto.ts فيه @Length(3, 20) مكرر.

الجزء التالت: المفاهيم اللي اتعلمناها

  • Modules: كل موديول بيجمع حاجتين related مع بعض. @Module({ imports, controllers, providers, exports })
  • Controllers: بتستقبل الـ HTTP Requests وترجع Responses. @Controller(), @Get(), @Post(), إلخ.
  • Services/Providers: логика البيزنس. @Injectable() عشان NestJS يحقنها.
  • Dependency Injection: Nest بيحقن الـ Services في الـ Controllers تلقائيًا عن طريق الـ constructor.
  • Module Exports: لو عايز Service يشتغل في موديول تاني، لازم الموديول الأصلي يصدّره.
  • DTOs & Validation: استخدام class-validator عشان validate الـ incoming data.
  • Pipes: ValidationPipe بيحول الـ DTO وي validate البيانات قبل ما توصل للـ Controller.
  • UUID: توليد IDs فريدة باستخدام مكتبة uuid.

🔵 المرحلة 2: الأساسيات المتقدمة (ابدأ هنا)

التالي ⬅️

  • Guards - الحماية والـ Authentication
    • إزاي تعمل Guard يمنع الدخول من غير تسجيل دخول
    • @Injectable() implements CanActivate
    • مثال: AuthGuard اللي بيشوف الـ JWT Token
  • Interceptors - تعديل الـ Request/Response
    • تسجيل وقت التنفيذ (Logging Interceptor)
    • تعديل الـ Response قبل ما يرجع
    • الفرق بين @UseInterceptors() و الـ global interceptor
  • Exception Filters - إدارة الأخطاء بشكل احترافي
    • عمل Exception Filter مخصص
    • التقاط أنواع معينة من الـ Exceptions
    • تغيير شكل الـ Error Response
  • Middleware - الـ Middleware في NestJS
    • الفرق بين Middleware و Guard و Interceptor
    • تطبيق Middleware على Routes معينة
    • Middleware للـ Logging أو الـ CORS
